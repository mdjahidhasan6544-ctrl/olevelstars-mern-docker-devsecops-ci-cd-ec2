PHASE 8 — EC2 DEPLOYMENT AUTOMATION
===================================

GitHub Actions must SSH into EC2 and deploy automatically.

Deployment steps on EC2:

1. Derive deploy path:

   DEPLOY_PATH="/opt/${REPO_NAME}"

2. Create deploy directory if missing:

   sudo mkdir -p "$DEPLOY_PATH"
   sudo chown -R "$EC2_USER":"$EC2_USER" "$DEPLOY_PATH"

3. Copy or generate:

   $DEPLOY_PATH/docker-compose.prod.yml
   $DEPLOY_PATH/.env

4. The EC2 `.env` file must include:

   DOCKERHUB_USERNAME
   REPO_NAME
   IMAGE_TAG
   NODE_ENV=production
   MONGODB_URI
   JWT_SECRET
   ADMIN_USERNAME
   ADMIN_PASSWORD
   BACKEND_PORT
   FRONTEND_PORT
   Any additional required runtime variables

5. Never print secret values in logs.

6. Login to Docker Hub on EC2 using DOCKERHUB_TOKEN.

7. Pull new images:

   docker compose -f docker-compose.prod.yml pull

8. Recreate containers:

   docker compose -f docker-compose.prod.yml up -d --remove-orphans

9. Verify containers:

   docker compose -f docker-compose.prod.yml ps

10. After successful deployment only, clean unused images safely:

docker image prune -f

11. Save rollback tags:

If CURRENT_IMAGE_TAG exists:

* copy CURRENT_IMAGE_TAG to PREVIOUS_IMAGE_TAG

Then write the new IMAGE_TAG to:

$DEPLOY_PATH/CURRENT_IMAGE_TAG

Do not run:

* docker system prune -a --volumes
* docker volume prune
* broad rm -rf commands
* commands that delete persistent data

Failure behavior:

* If deployment fails, show:

  * docker compose ps
  * recent frontend logs
  * recent backend logs
* Do not print secrets.
* Exit with non-zero status.
